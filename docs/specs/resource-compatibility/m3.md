# M3: document fidelity and resource settings

M0–M2 were committed as `7dc5d8c` before this implementation. Their baseline is 1,201 passing tests, 19 corpus and six exact-resource CLI scenarios. M3 implements the next [six plan items](tasks.md#m3--close-document-fidelity-and-settings-gaps) without adding a vendor runtime, copied adapter, third-party dependency or a second save system.

## Delivered behavior

| Plan requirement | Implementation and acceptance |
|---|---|
| Consistent settings | `ResourceText` centralizes exact-resource decoding, encoding, newline handling, JSON indentation and validation. Precedence is resource → typed project → legacy project preferences → detected document → defaults. Project/package saves and CLI mutations use the same adapters; production GUI Save As retains settings and document state. Resource-level booleans retain precedence even when false. |
| JSON structure | Typed paths retain literal/nested key distinctions, nulls, raw numeric/boolean scalars, empty objects/arrays, numeric objects and sparse array positions. Existing key order is retained unless alphabetical output is selected. Edited scalars become strings; later saves cannot revive an obsolete numeric cache. |
| YAML dialects | Exact resources unwrap a locale root only for `rails-yaml`; generic resources retain it as an ordinary key. A restricted block-map/sequence parser retains typed keys, JSON-compatible scalars, null/empty nodes and supported block scalar values. Unsupported syntax is review-only with warnings and blocked saves. |
| ARB metadata | Descriptions map to `TranslationItem.Comment`; `arb.placeholders` contains an editable JSON object. Edits merge with original per-key metadata, retaining unknown fields and document headers. Renames carry metadata; explicit empty comments remove descriptions; an empty placeholder object clears placeholders. Deleted messages lose their paired metadata; unrelated orphan metadata remains. ICU messages remain whole strings. |
| Java properties | The document parser handles unescaped key separators/whitespace, escaped keys, Unicode escapes, continuations and comment lines. Exact saves preserve raw unchanged records, comment text, key order and escape style. Explicit encoding, newline, ordering and `UnicodeEscapes` policies are supported; malformed escapes and unknown overrides are diagnosed. |
| Identity and save safety | Typed identity owns keys and destinations. Moves use the destination descriptor's prefix and locale, including literal target keys. Destination reassignment retains resource/entry IDs; stale vendor key/file caches do not route writes. Empty documents, package review state, rollback and existing recovery remain supported. |

### Option and format rules

Input encoding selects how existing bytes are decoded. Output encoding selects the newly written bytes; it never reinterprets the source. When transcoding changes the required decoder, the native resource records the written encoding for its next reopen. Failed saves restore descriptor, detected options and document data with the existing journal's file rollback. Known text encodings are UTF-8, UTF-8 BOM and ISO-8859-1/Latin1; invalid names and enum values identify the resource/field instead of silently falling back.

Layouts and delimiters control **new unbound key placement**. Literal/dotted layouts create literal properties; nested layout splits the selected delimiter. Existing typed identities keep their physical meaning until an explicit typed rename/move: changing a preference does not flatten or reinterpret existing keys. Formats with literal IDs, such as ARB, properties and RESX, keep those IDs literal.

Array preservation is the default. `ContiguousIndexes` converts only nonempty numeric objects with canonical consecutive keys `0` through `n-1`; empty/sparse objects remain objects. `Disabled` diagnoses actual arrays instead of inventing another shape. Deleting an array entry preserves its index as a null slot. JSON whitespace is regenerated according to the selected/detected indentation; this is semantic preservation, not byte-identical formatting.

Block YAML accepts two- or four-space indentation. Native tab/compact overrides are rejected. A legacy imported YAML tab setting is adapted to two spaces with a source-field warning, and its original external configuration remains in the compatibility envelope. Anchors, aliases, tags, merge keys, nonempty flow collections, directives, multiple documents and other unsupported forms cannot be rewritten. Their review preview may be incomplete, which the diagnostic states. The legacy folder reader retains its explained compatibility heuristic: a single locale root matching the filename is treated as a locale wrapper and recorded in `yaml.locale`. Declared generic exact resources do not use that heuristic.

Java `UnicodeEscapes` supports Preserve, Always and Minimal. Preserve keeps unchanged source records and uses the observed file escape preference for edits. Alphabetical output retains comment text but does not promise original per-key comment associations; Preserve retains the original record order. Duplicate Java keys are rejected by exact resource identity validation. Source comments are separate from Toucan's native review comments.

These guarantees apply to exact-resource requests. Optional folder-only plugin APIs keep their existing behavior and formatting limits; they are not silently upgraded into file-level adapters. The existing native review/sidecar policy is retained. This milestone does not introduce external metadata-conflict preview or a structured ICU editor.

## Public format references

The properties parser follows the public rules for unescaped key delimiters, whitespace, continuations and Unicode escapes in [Java Properties documentation](https://docs.oracle.com/en/java/javase/26/docs/api/java.base/java/util/Properties.html). YAML support is deliberately a subset of [YAML 1.2.2](https://yaml.org/spec/1.2.2/). ARB description/placeholder mapping uses the format documented by [Flutter internationalization](https://docs.flutter.dev/ui/internationalization). Implementations and regression inputs are independently authored; no vendor implementation resource was used.
