# M2: migration module and exact resource IO

M2 completes the migration and exact-resource slice in [the implementation plan](tasks.md#m2--isolate-migration-and-use-exact-resource-io). It builds on M0/M1 without replacing the existing project lifecycle, save journal or plugin registration system. No installed BabelEdit runtime, adapter, UI asset or dictionary is read or shipped by this implementation; no new third-party dependency is added.

## Delivered behavior

| Requirement | Implementation | Executed evidence |
|---|---|---|
| Isolated migration | `Toucan.Modules.Compatibility.BabelEdit` registers `IProjectCompatibilityImporter` through `AddToucanDefaults`, used by Avalonia and CLI. It references only Common and Abstractions. The neutral `CompatibilityProject` is mapped into native settings by Core. Vendor schema/configuration and metadata interpretation stay in the module. | Architecture, composition, eight-module catalog, GUI and CLI tests |
| Validated input | XML DTDs/external entities are prohibited. Unknown schemas/frameworks, missing packages/paths/locales/files, duplicate package/language/resource mappings and escaping references are rejected before workspace replacement. Diagnostics identify source/resource and field. | `InvalidMigrationDoesNotCreateNativeManifest`, `XmlExternalEntitiesAreProhibited`, `MissingFilesAndEscapingPathsAreRejectedForEveryExactFormat` |
| Explicit resource IO | JSON, YAML, ARB, Java properties, RESX/RESW and Laravel PHP use declared paths, locale and package through file-level contracts. Original basenames and unrelated siblings do not determine the language or become extra resources. Unsupported exact formats receive diagnostics. | `DeclaredFilesAndLocalesSurviveMultiplePackagesNativeReopenAndLastEntryDeletion`; six GUI and six CLI cases |
| Package dispatch | Package loading/saving uses the selected exact-file adapter. Creation writes the selected format; removal uses validated destinations and journals. Empty documents remain registered and writable. There is no package JSON fallback. | `PackageServiceDispatchesExactFormatAndClearsEmptyDocuments`, `PackageCreationUsesTheSelectedFormatAndKeepsExistingResources` |
| Physical containment | Both separator styles normalize; containment uses platform case rules and resolves existing links/junctions before IO, including missing files under existing linked directories. Duplicate physical destinations are rejected during migration. External resources must be copied into the project explicitly. | Real Windows junction test with internal and external targets; per-format missing/escaping tests |
| Existing lifecycle and recovery | Invalid target migration preserves the active workspace and unsaved edits. Exact saves participate in the lifecycle's journal or create a journal for direct CLI/package calls. Every requested destination must be protected. An unresolved journal cannot masquerade as an active save. Last-entry deletion rewrites the declared document rather than leaving stale translations. | GUI workspace-preservation and same-folder reopen tests; injected second-write failure; direct-save journal-ownership regression; existing recovery suite |

Original `.babel` bytes remain unchanged. Native reopen succeeds after removing that source file. Native entry identities, comments, descriptions and per-language approvals survive the tested GUI/CLI workflows. RESX exact IO retains opaque typed resources, headers and metadata while editing strings; ARB document headers survive deletion of the final message.

## Supported subset and boundaries

Declared schema **1.3** and the existing minimal versionless legacy subset are supported. A framework and nonempty package/resource maps with explicit path and language are required. Omitted language lists are derived from the URL declarations. Unknown declared schema versions are rejected; this is not certification of every feature of schema 1.3 or every BabelEdit version.

Exact migration supports the six format families above, including `.yml`/`.yaml` and `.resx`/`.resw`. PO and XLIFF remain usable through their existing folder APIs, but their exact migration requests are explicitly unsupported. Legacy native folder projects and folder-only plugins keep their existing APIs; migrated projects persist authoritative resource descriptors.

The old native `babelImport` read bridge remains for migration of existing manifests. Its payload is placed in a versioned compatibility envelope; it is not a dependency on the compatibility module. The module owns its serialized source metadata and never writes the external project format.

M3 still owns full settings/fidelity behavior: generic YAML locale-root heuristics and unsupported YAML constructs, layout/delimiter/array rules, ordering/indentation, ARB description editing and comprehensive Java escape/encoding policies. This milestone verifies exact routing and the stated preservation subset, not lossless editing of arbitrary format features. M4–M7 remain unaccepted.
