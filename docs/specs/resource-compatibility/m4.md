# M4 spreadsheet exchange

M4 provides native spreadsheet exchange and an optional public-header compatibility mapping. Core owns workbook IO and planning; the compatibility module registers a column descriptor through existing dependency injection. No installed vendor resource, implementation, artwork or new dependency is used. The compatibility mapping is independent of the project migration reader.

## Workbook dialects and data policy

The Excel export command offers **Toucan (presence and typed paths)** and, when registered, **BabelEdit-compatible (shared comments)**. Toucan is the default selection. Both write translation strings as text, including leading `=`, `+`, `-`, `@` and apostrophes. Formula cells in imported data are rejected rather than evaluated.

| Schema | Columns | Blank and omitted data |
|---|---|---|
| Toucan v2 | `Package`, `Key`, `Path`; each locale has value, ` present`, optional ` comment` and ` approved` columns | `present=false` omits the whole locale unit; `present=true` with a blank value explicitly clears it. Missing metadata columns leave metadata unchanged. Blank metadata cells in present columns clear comments/reset approval. |
| Package exchange | `Package`, `Translation ID`; locale values and optional ` approved`; optional shared `Comment` | Blank value cells clear. Absent language/metadata columns leave existing data unchanged. |
| Legacy Toucan | `Key`; locale values; optional `Package`, `Comment`, shared `Approved` and per-locale ` approved` | Retains legacy blank-as-clear and shared-approval semantics; a per-locale approval column overrides the shared flag. Missing package means `main` for a single-main-package project; package-aware projects require an explicit Package column. |

Toucan v2's `Path` is the JSON array of property/index segments from neutral resource identity, with `Key` showing its readable selector. A blank path permits package/key matching when unambiguous. Typed paths preserve literal dotted keys, nested properties and array indices. Package and key text are exact, including whitespace in keys. Locale headers are case-insensitively unique; matching to project locales is exact. Unknown headers, orphan metadata columns, duplicate rows, invalid flags/paths, conflicting key headers, extra worksheets and rows containing data without an ID are errors.

Toucan previously emitted the same unmarked `Package`/`Translation ID` headers as the compatibility mapping. Readers recognize their shared schema without claiming which application produced a workbook. Existing static `ExcelService.Import/Export` callers retain that schema and historical metadata through an isolated legacy bridge; the application's new path uses neutral tables and resource identity, without `babel.*` metadata.

Compatibility export refuses language-specific comments, missing locale units or multiple typed identities with the same textual ID when its columns would lose that distinction. Use Toucan v2 for those cases. A user preparing a legacy/package workbook must remove an entire language column to omit it; an empty individual cell is a clear. These rules are shown in the preview and remain explicit instead of guessing from XLSX cell storage.

## Preview and application

`SpreadsheetPlanner` copies the workspace and matches package/key/language plus optional typed path. It reports additions, value edits, explicit clears, metadata-only edits and conflicts. Unknown packages/languages, duplicate or ambiguous entries, parent/child value collisions and additions lacking a unique exact resource destination block the entire import. It never creates a package or guesses a language destination. Indexes bound matching work rather than scanning the entire workspace for every workbook unit.

The preview lists row numbers, package/key/language, before/after values, comments and approvals with counts. Conflicts disable Apply; cancellation changes no models, history or files. Strict approval validation runs against the proposed values. A workspace revision check rejects stale acceptance after concurrent editing.

Accepted changes use one structural history record, the normal translation store, dirty notifications, validation results and recovery drafts. One Undo restores all values, metadata, identities and additions together; Redo restores the accepted result. Native save/reopen retains metadata-only changes. Structural replacement now retains saved baselines until save/reload, fixing a discovered store bug that otherwise made edited entries look newly added to crash recovery.

## Limits

Before ClosedXML loads a workbook, archive checks allow at most 20 MiB compressed, 100 MiB expanded and 2,048 ZIP entries. Before building the edit set, worksheet checks allow at most 50,000 rows including headers, 256 columns and 200,000 potential locale units. Typed paths contain at most 128 segments; export checks Excel's 32,767-character text limit. There must be exactly one worksheet. Damaged archives and supported malformed-package exceptions become actionable format diagnostics. Large parsing remains synchronous, within these limits.

## Executed acceptance

The complete Windows solution regression run passes **1,279 tests**: Core 1,001, Avalonia 267, plugin harness 11; no failures or skips. The 27 new `SpreadsheetExchangeTests` cases cover dialect mapping, typed/package identity, mixed approvals, reordered columns, Unicode, sparse languages, explicit clears, missing metadata, malformed/ambiguous headers and rows, destination conflicts, formula-like text/apostrophes, formula rejection and size limits. All five existing `BabelExcelTests` remain passing.

Seven new headless `SpreadsheetImportFlowTests` cases cover detailed previews and disabled acceptance for conflicts, no mutation on cancel/conflict, exact count/application agreement, one Undo/Redo, metadata/native reopen, stale revision, strict validation, compatibility registration and recovery after a simulated restart. Existing `BabelImportFlowTests` also pass. The unchanged frozen M0 sample plugin is verified by the full suite and evidence collector. No vendor corpus changes were made.
