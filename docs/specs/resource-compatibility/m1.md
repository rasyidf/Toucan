# Resource compatibility: M1 contracts and identity

M1 implements the neutral foundation in [the work plan](tasks.md#m1--add-neutral-resource-and-document-contracts). M0's [baseline](acceptance.md) remains historical evidence. The implementation builds on commit `ea3d255`; M0 documentation/tooling already in the working tree was preserved. M1 introduces no BabelEdit runtime, copied vendor adapter or third-party resource dependency.

## Delivered behavior

| M1 requirement | Implementation | Acceptance tests |
|---|---|---|
| Optional exact-file IO | `IResourceLoadStrategy`, `IResourceSaveStrategy`, `IResourceDiscoveryStrategy`; requests/results include options, diagnostics, state and cancellation | `ExactFileRequestNeverFallsBackToFolderPlugin`; `ExactWriteRejectsForeignEntriesAndCancellationWithoutTouchingTheFile` |
| Stable identity | Descriptor ID is independent of destination. Entry identity records resource, package and typed property/index path. Initial JSON IDs derive from resource/path; saved IDs survive rename/move | `LiteralNestedArrayAndNumericObjectAddressesSurviveEditAndNativeReopen`; `MoveDuplicateAndDeletePreserveEntryMetadataAndExplicitDestination` |
| Typed settings | Nullable layout, delimiter, arrays, indentation, ordering, encoding, newline and empty policy; resource → project → detected → defaults | `SettingsResolveResourceThenProjectThenDetectedThenDefaultsWithoutMutation`; existing encoding/newline and empty-value suites |
| Document state | One opaque state object per document, including empty documents; state advances after successful writes | `EmptyDocumentAndUnknownCompatibilityDataSurviveNativeRoundTrip` |
| Native migration | Resource schema 1, versioned compatibility envelopes, old `babelImport` reader and runtime shims; unknown native/envelope/document/option fields retained | `OldBabelManifestMigratesIntoVersionedEnvelopeWithoutLosingUnknownFields`; `FutureNativeResourceSchemaCannotBeOverwritten` |
| Structural editing | Shared typed rename/move/copy; legacy key setter updates identity. Structural snapshots use the normal undo stack; crash drafts retain identity, metadata and documents | `CollisionRenameDuplicateDeleteUndoAndSavePreserveTypedIdentity`; `TypedLiteralRenameMetadataAndDocumentStateSurviveCrashRecovery` |
| Existing plugins | Folder/profile interfaces remain unchanged; optional factory capabilities use default members. Package/API advances to 1.2 | `FrozenM0PluginLoadsAndSavesWithoutRecompilation`; existing contract/host/profile/legacy-project suites |

JSON is the first document-aware adapter. Native JSON and the existing JSON `.babel` path now use the same neutral model. Other formats retain their folder strategies until M2 adds exact-file adapters. Unsupported exact-file requests return diagnostics and never substitute a folder scan.

Framework/configuration translation remains in `BabelProjectReader` until M2. It maps known settings to typed options and retains original project metadata in `Compatibility["babeledit"]`. Moving the importer into its own module and validating external schema versions remain open.

## Selectors and persistence

`Namespace` remains a backward-compatible editor/plugin selector. Typed writers serialize `Identity.Path`, not the selector. Ordinary keys keep their spelling. Colliding literal/nested names and reserved characters use escaped selectors, with deterministic disambiguation for remaining collisions. Tree construction understands escaped separators.

Literal `"a.b"`, nested `{"a":{"b":...}}`, literal `"items[0]"`, array indices and numeric object properties stay distinct. A literal property's rename keeps it literal. `RenameKey` accepts explicit segments, `Move` retains entry ID while changing destination identity, and `Copy(..., duplicate: true)` creates a new entry ID. Native review state is matched by resource address before legacy selector fallback.

Existing string-key search, bulk/review and workspace operations use these unique selectors. Typed destination changes participate in dirty tracking. Undo snapshots and crash drafts preserve identity and format metadata; Save As copies documents and compatibility envelopes. The existing journal remains the recovery mechanism, including opening an interrupted JSON write far enough to offer restoration. The added-language workflow clones typed key paths rather than reconstructing them from display strings.

Spreadsheet export prefers neutral identity over stale imported metadata. Its current schema cannot distinguish literal and nested IDs with identical text, so ambiguous export is rejected before writing; export resources separately until M4 provides an appropriate dialect. `SpreadsheetExportUsesRenamedResourceIdentityAndRejectsAmbiguousPaths` covers this boundary. `EditedScalarDoesNotRegainItsOldTypeFromNativeMetadata` ensures old numeric metadata cannot undo a string edit.

## Frozen binary and verification

`tests/fixtures/resource-compatibility/m0-sample-plugin.zip` contains the unchanged M0 sample plugin DLL, desktop DLL and manifest. Tests verify their hashes against M0 evidence before installation. It is Toucan's own MIT-licensed sample build, contains no third-party runtime DLLs, and lets CI test the old compiled artifact without rebuilding it against new contracts.

The binary registers its format, creates a project, saves and reopens values against API 1.2. Its absent exact-file capability is reported accurately. This certifies the captured sample, not every independently published plugin or downgrade to an older host.

Executed on Windows x64, SDK 10.0.401, xUnit v3/VSTest. Final counters, raw-result hashes, CLI results, fixture provenance and source hashes are in [M1 machine-readable evidence](evidence/m1-verification.json). No commit was created by this task.

## Remaining milestone boundaries

- M2 owns non-JSON exact-file adapters, importer modularization, external schema validation, explicit multi-package language destinations and reparse-point policy. M1 provides lexical containment. Adding a language to a resource-aware multi-package project reports that explicit destinations are needed instead of guessing files.
- M3 owns full fidelity and applying every format-specific option, including array policy, arbitrary output encodings and ARB/YAML behavior. M1 defines and transports these options; it does not certify every writer. JSON document state retains opaque nulls/containers; legacy folder-only calls cannot retain state they were never given. Array deletion/compaction policy remains M3.
- M4 owns workbook dialect selection, preview/undo, omitted-cell semantics and structured exchange. M5–M7 retain framework, scanner and spelling/provenance work.
- Verification is local Windows/headless, not new macOS/Linux packaged-app or live-provider certification.
