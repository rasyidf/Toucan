## Addendum: open a project from a service (2026-11-05)

Not in the original plan. **Open from a service** (start screen, Sources menu, command `toucan.sources.open-from-service`) picks a service, an account and a project, makes a local folder (default `Documents/Toucan/remote/<service>/<project>`, changeable), writes a manifest with a `primary` connection, pulls every document, detects the framework and opens the project. The recent list shows it as `crowdin:<project>`. Core: `RemoteProjectBootstrap`; UI: `OpenFromServiceViewModel` and dialog; `ProjectService.DetectFramework` was split out of project loading for it. Only services that store files are offered. Tested with a file-service stand-in in the editor and live against a real Crowdin project (`LiveOpenAProjectFromCrowdinIntoANewFolder`). Not covered: an account chosen in the dialog is bound to the new folder only on this machine; the project must use paths a framework profile detects (a Crowdin source file at the project root next to `locales/<lang>/` exports opens with no languages until paths line up).

## Phase 8: Hardening (v0.31)

- [x] 8.1 Profile pull, plan and push at 10,000 keys × 10 locales; record timings and memory; keep the editor responsive during sync. Done in `SyncScaleTests` (100,000 translations, Debug build, one developer laptop): plan 0.3 s with 2,000 changes, delivery state 0.15 s, baseline write 0.1 s and read 0.4 s (40 MB), push of 1,000 changes in batches of 100 in 2.1 s. The first measurement of that push was 15 s because every result rewrote the baseline and rebuilt its index; the executor now indexes once and writes the baseline only when a result changed it. Delivery states are recomputed 250 ms after the last edit and the baseline file is re-read only when it changed, so typing does not walk the project per keystroke. Memory was not measured and pulls at this size were not profiled.
- [x] 8.2 Migration checks for `sources` in project files, accounts, baselines and journals from each supported preview version. Done in `SourceMigrationTests`: unknown fields are ignored, fields added later get defaults, a file from a newer build is set aside and never overwritten, projects from before `sources` load with none. Only one preview format exists so far, so there is no older preview to migrate from.
- [ ] 8.3 Packaged end-to-end checks on Windows, macOS and Linux including the OS credential stores.
