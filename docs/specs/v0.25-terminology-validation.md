# v0.25 terminology and validation

## Project terminology

The Dictionary panel stores source terms, descriptions, forbidden-term flags and translations by language in `toucan.tproj`. Select a term to edit it, choose a language code to edit that translation, then Save term. New term clears the form. Delete removes the complete term and its translations. Changes use configuration history and survive normal project persistence/recovery; undo and redo restore them.

Terms matching the selected source string appear above the editor. Selecting a preferred match asks for a target language and appends its translation to that field. This is an explicit edit with undo and dirty tracking; it clears approval. Forbidden terms cannot be inserted. The panel offers suggestions alongside the editor rather than a popup inside the caret position. Matching ignores case, respects word boundaries for alphabetic words, and allows contiguous Chinese/Japanese text.

CSV columns are `term,description,forbidden,language,translation`, in that order. Export writes one row per term/language; a term without translations has an empty language and translation. Quoted commas, newlines and doubled quotes are supported. Import validates the complete input before changing configuration, merges terms by case-insensitive source term, and replaces each imported term's complete definition. Duplicate term/language rows and conflicting definitions are errors. Import can be undone.

The `glossary` validation rule warns when a target contains a forbidden term or omits the preferred translation of a source term. It does not automatically rewrite text or block draft saves. Rule enable/severity settings apply normally.

Translation previews capture the current project's glossary, including unsaved terminology. Relevant source matches and forbidden terms are included in provider options; AI receives the glossary prompt variable and contextual instructions. DeepL receives terminology in its context. Other providers may ignore unsupported options; Toucan does not claim native glossary enforcement by those services. AI analysis receives preferred terminology as its glossary input.

## Validation policy

Effective rule policy merges application defaults with per-rule project overrides. An omitted project rule inherits its default; a project override can re-enable a default-disabled rule. IDs are case-insensitive. Invalid severity values retain the finding's default severity. Disabled rules are not executed. Policy applies to inline and manual desktop checks, CLI checks, saves, native approvals and plugin workspace edits.

Validation while typing retains the existing 300 ms debounce. Issue navigation selects the affected language field when present. Normal draft saves remain available with findings. Explicit strict save/approval checks treat configured Error findings as blocking. Save As retains validation overrides and terminology. Document saves validate the committed projection, including the pending edits being saved.

## Message syntax

The `message-syntax` rule validates the ICU MessageFormat 1 subset containing `plural`, `selectordinal` and `select`, including nested branches. Each requires `other`; duplicate selectors, invalid plural selectors and unbalanced braces are errors. Nonnegative integer plural offsets, exact numeric selectors, simple arguments, and number/date/time arguments are accepted. ICU's apostrophe-friendly quoting and doubled apostrophes are recognized. Nesting is limited to 64 levels.

Source/target comparison checks argument names and types and required source select labels. Plural categories may differ by language. This is structural validation, not an ICU formatter or locale-specific CLDR category certification. It does not certify number/date skeletons or style patterns, select-label reachability, exact-selector preservation, or every argument occurrence in each possible execution branch. Legacy `choice`, MessageFormat 2 and nested formatter styles are unsupported. Complex-message detection requires an ICU plural/select header; plain non-ICU braces continue through the existing placeholder rules.

ICU messages use this structural comparison instead of regex token counts, avoiding false mismatches when target plural categories differ. Existing `{{name}}`, `{name}`, `{0}`, printf, colon and template-literal placeholder checks remain available for non-ICU text.

Syntax reference: [Unicode ICU MessageFormat](https://unicode-org.github.io/icu/userguide/format_parse/messages/).

## AI review

Issues offers Analysis strictness per project: Strict includes confidence 0.4+, Balanced 0.6+, and High confidence only 0.8+. Changes use configuration undo and persistence. A result arriving after the workspace changes is discarded.

An AI analysis finding offers Re-translate. It opens the existing translation preview for the source/target pair with overwrite enabled. Acceptance remains explicit; cancellation changes no text, and accepted edits follow existing grouped undo and stale-preview checks. Ambiguous display keys require direct entry selection. API credentials and network-service acceptance are separate from local workflow tests.
