# v0.25 release readiness

## Execution plan

1. Restore and build the maintained solution. Apply rule enable/severity policy consistently to manual, inline, CLI, save, native approval and plugin approval validation. Add regression coverage for inheritance and approval eligibility.
2. Add persisted project terminology, preferred/forbidden terms, language translations, descriptions, CSV exchange, selected-string matches and editor suggestions. Route terminology into validation and supported translation requests.
3. Add nested ICU plural/select syntax validation, required branches and argument comparisons. Document supported syntax and explicit limits; retain existing placeholder dialect checks.
4. Finish AI finding re-translation through the existing preview/acceptance flow and expose analysis strictness. Preserve stale-result checks, undo and dirty tracking.
5. Resolve workspace integration coverage and retain safe format-save boundaries. Do not enable a format for targeted writes without fidelity evidence.
6. Run focused xUnit regressions, then the full maintained build and suites. Validate documentation headers and regenerate the index. Reconcile roadmap and known issues against passing evidence.

## Constraints and acceptance

Draft saves remain available with validation findings. Approval follows effective configured policy. Suggestions enter through workspace commands. Existing project/plugin contracts remain compatible. Native Windows accessibility, real external connectors and service credentials require their own execution evidence; automated tests cannot accept those gates.

Final validation uses xUnit first for behavior and integration, MVVM review for command/binding separation, then doc-status for accurate headers, task counts and links. Build and test failures are recorded before claiming completion.
