# Toucan v0.25.0 — Terminology and message-aware validation

Toucan v0.25.0 makes translations follow project vocabulary and keeps executable message syntax intact. This is preview software; keep translation files in version control.

**Release status:** version bumped on 2026-11-05. Automated checks pass: 1,658 passed tests (Core 1,259, desktop 388 with one external connector test skipped, plugin harness 11). Native Windows accessibility checks were run on a separate machine; their evidence is not stored in this repository. Packages for this version have not been built yet; v0.24.0 download guidance is in its [release notes](v0.24.0.md).

## Highlights

- **Project glossary.** The Dictionary panel keeps preferred and forbidden terms with per-language translations and descriptions, imports and exports CSV, shows matches for the selected source string and inserts a preferred term only when you choose it.
- **One validation policy everywhere.** Rule enable and severity settings, with per-project overrides, now apply the same way in the desktop app, CLI, save, approval and plugin edits. This closes APP-06.
- **ICU message checks.** Nested plural and select messages are checked for required branches and argument consistency. Supported syntax and limits are in [terminology and validation](../specs/v0.25-terminology-validation.md).
- **AI findings you can act on.** Analysis strictness is set per project. A finding's Re-translate action opens the normal preview; accepting it is explicit and undoable.
- **Safer saves in document projects.** Formats declare whether a save rewrites everything or only the documents it plans, and only verified formats (JSON and namespaced JSON) use targeted writes. `toucan set` and `toucan translate` no longer rewrite every file of a document project. Adding a key asks for a destination document only when more than one fits.

## Fixes you will notice

Explicit resource mappings survive project loading, JSON comment sidecars no longer appear as languages, pending document edits are validated before strict saves, and external changes stay visible after targeted autosaves. Native structural undo restores clean dirty state and stable entry identities, and hiding a language gives its width back to the comparison columns. See the [full changelog](../../CHANGELOG.md#0250---2026-11-05).

## Compatibility and known limits

The app version is **0.25.0**. `Toucan.Plugins.Abstractions` stays at **1.2.0**; existing folder plugins remain supported. Projects and settings can change before v1.0. Back up existing projects before migration.

Other formats keep their safe whole-project saves until each has fidelity fixtures. ARB is next, but needs a decision on where field comments live first. Release pipeline, signing, installer acceptance and external connector revalidation remain open; see [known issues](../known-bugs.md).
