Toucan roadmap: v0.21 to v1.0

v0.26 to v0.29 shipped in the v0.26.0 pre-release. Feature work is frozen; the v1 checklist maps each v1.0 gate to correctness, contract, evidence, distribution, performance and release tasks.

in-progressUpdated 2026-11-25Edit on GitHub ↗

#Product goal

Open a localization project, understand what needs work, translate with context, review confidently, and save or synchronize without losing information. Local files remain a first-class workflow; online connections are optional.

The order is reliability → daily workflow → content sources → distribution → stabilization. Each release has one main outcome and a completion gate. Versions describe the intended sequence, not dates or a promise to ship unfinished work. Split a milestone further if its scope grows; do not move unresolved safety work into v1.0 merely to keep the version schedule.

#Maintaining this roadmap

This file lists open work only. Remove shipped tasks instead of ticking them, except in the v1 checklist, where closed items are ticked until 1.0 ships so each gate shows its progress. Add user-visible changes to CHANGELOG.md under [Unreleased], regenerate the website changelog with python3 tools/generate-changelog.py, lasting capabilities to completed-features.md, and remove resolved issues from known-bugs.md. Keep the README roadmap and website summary aligned, then refresh docs/INDEX.md.

Existing bugs are linked by ID instead of duplicated here. Completion gates describe acceptance criteria; checkboxes describe implementation work. The header counts release tasks, v1.0 gates, and deferred tasks separately.

#Release overview

The 2026-10-25 source audit distinguishes implemented UI and compatibility work from unfinished product workflows. v0.24 already implements its editor/onboarding features; its remaining task is release acceptance. The main plugin toolbar and macOS native menu are implemented. Later milestones retain the work that their existing foundations do not yet deliver.

#v0.21: File fidelity and CI

Outcome: supported formats can be edited without losing information, with automated protection against regressions.

Status: complete. The cross-platform CI workflow is fixed and finalized; no CI work remains open. Coverage stays a report, not a release criterion.

Completion gate: every format advertised as editable passes its documented fidelity fixtures, and CI catches the known regression cases.

#v0.22: Safe saves and recovery

Outcome: users can preserve incomplete work and recover from interrupted persistence.

Completion gate: failure scenarios preserve a recoverable copy and never report unsaved work as saved.

#v0.23: Extension platform

Shipped in v0.23.0. The extension platform (registration/activation split, command registry, desktop contribution package, host services, workspace API, compatibility checks, SDK harness and sample connector) is in CHANGELOG.md and completed-features.md. The sample connector built outside this repository loads on desktop and in the CLI, its command is in the palette and a menu with a reassignable shortcut and becomes unavailable when its workspace closes, and a plugin batch edit behaves like a native edit through undo, save failure, recovery and reopen.

The upstream release records its connector acceptance as passed. Revalidation of the merged source build and the production connection-management gap remain tracked in APP-05 and QA-03.

#v0.24: Editor comfort and onboarding

Outcome: a new user can open a project and complete a keyboard-driven translation session comfortably. References: QA-03. Implementation and Windows automated evidence are in editor-comfort acceptance.

Completion gate: a user can work through 100 strings without losing their place or needing a mouse for routine actions; accessibility and layout issues found in that flow are resolved.

#v0.25: Terminology and validation

Outcome: translations follow project vocabulary and preserve executable message syntax.

Status: shipped as app version 0.25.0. Local verification is archived in v0.25 readiness; native Windows accessibility checks were run on a separate machine. Supported behavior and limits are in terminology and validation. The ARB comment decision moved to V1-10.

Completion gate: glossary and message fixtures detect meaningful errors without blocking draft saves; accepting a suggestion follows normal undo and dirty tracking.

#v0.26 to v0.29: Review correctness and content sources

Shipped together in the v0.26.0 pre-release (2026-11-25): review state, Needs review filters, reject and approve with comment, review history, the strict-validation push hold-back for key/value services, plugin API 1.3, accounts, the local-folder source, the sync engine, the Sources panel, toucan sources commands, the Crowdin connector (preview) and Open from a service. Details are in CHANGELOG.md and content-sources tasks.

Open items moved to the v1 checklist: live Crowdin writes and failure cases (V1-15, V1-16), the Sources accessibility pass (V1-52) and packaged keyring checks (V1-45, V1-60). Staged plugin installation, publisher signatures and entitlement checks from the v0.29 plan did not ship and move to 1.x with the plugin feed.

#v0.30: Distribution and updates

Outcome: releases are repeatable, installable, and discoverable. References: REL-01, REL-02, REL-03, REL-04.

Tasks are in the v1 checklist.

Completion gate: a release can be built from its tag and installed/upgraded on each supported platform, with explicit platform limitations and no manual artifact patching. Automatic in-app installation is deferred.

#v0.31: Performance and release candidate

Outcome: the complete workflow has measured limits and survives upgrade and failure scenarios. Reference: QA-02.

Proposed performance budgets: usable editor within five seconds for the reference fixture, warm search within 200 ms, and responsive typing while persistence runs. Confirm or revise these budgets against named hardware before claiming them; they are not current measurements.

Tasks are in the v1 checklist.

Completion gate: measured budgets are met or the supported scale is explicitly narrowed, migrations pass, and no unresolved data-loss or silent-overwrite issue remains.

#v1.0 release gates

Version 1.0 ships only when every gate below is checked. Feature work is frozen: from here only correctness, contracts, distribution, verification and release work lands; everything else is 1.x (see Future plan). The checklist below owns the remaining v0.30 and v0.31 tasks; those sections keep only their outcome and completion gate.

  • ☑Done: G1 Formats. Every format advertised as editable preserves its documented semantics and metadata; unsupported constructs have safe, visible handling. Tasks: V1-10 to V1-12.
  • ☐To do: G2 Recovery. Failed saves, crashes and interrupted synchronization preserve recoverable work and accurate pending state. Tasks: V1-13 to V1-15.
  • ☐To do: G3 Connectors. Stable online connectors handle concurrency, permissions, partial success and retry/recovery; preview connectors are clearly identified. Tasks: V1-15, V1-16.
  • ☐To do: G4 Contracts. Plugin API, project, account, sync-state and source-protocol contracts are frozen, with a written migration and downgrade policy and migration tests from every released preview. Tasks: V1-20 to V1-27.
  • ☐To do: G5 Evidence. Daily editing and review workflows pass automated and packaged-build checks on Windows, macOS and Linux, each backed by a machine-readable record for the release commit. Tasks: V1-30 to V1-32, V1-60.
  • ☐To do: G6 Distribution. Installation, update discovery, upgrade, uninstall and settings preservation are tested and documented per OS. Tasks: V1-40 to V1-46.
  • ☐To do: G7 Performance and accessibility. Both have recorded verification; budgets are met or the supported scale is narrowed and published. Tasks: V1-50 to V1-52.
  • ☐To do: G8 Release. A release candidate is published, known limitations are published, and no release-blocking issue remains. Tasks: V1-60 to V1-62.
